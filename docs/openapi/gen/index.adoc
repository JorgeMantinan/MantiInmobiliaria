Alta con los MISMOS filtros que `GET /api/v1/inmuebles`: un rango inválido (precioMin > precioMax, precios negativos, habitaciones < 0) responde 400 igual que el listado. [.solicitarPasswordOlvidada]
==== solicitarPasswordOlvidada

`POST /api/v1/auth/password/forgot`

Pide el enlace de restablecimiento de contraseña

===== Description

Si el email corresponde a una cuenta CON contraseña, se envía un enlace `FRONTEND_URL/restablecer?token=<opaco>` (el token, opaco y de un solo uso, caduca en `auth.password-reset.ttl`, 15 min por defecto). Si la cuenta ya tiene un enlace vigente no se envía otro (el primero sigue siendo válido). El envío del email es asíncrono: el 202 no espera al proveedor. La respuesta es SIEMPRE `202 Accepted` aunque la cuenta no exista (sin enumeración de emails ni por tiempo de respuesta) y aunque el proveedor de email falle. Rate limit: 5 peticiones/hora por IP.

===== Description

Idempotente por DISEÑO (la constraint `uq_swipes_usuario_inmueble` garantiza una fila por pareja): 201 en la primera decisión; repetir la MISMA decisión → 200 sin crear fila; cambiar de opinión → 200 actualizando. No requiere cabecera `Idempotency-Key`: la unicidad natural es la idempotencia. Ante una carrera de inserción (doble tap del frontend) el servicio reintenta una vez en una transacción nueva y responde 200; sólo si la relectura sigue vacía devuelve 409. 404 si el inmueble no existe o está eliminado.

[.diagnosticoTelegram]
==== diagnosticoTelegram

`GET /api/v1/admin/telegram/diagnostico`

Lista los chats que han escrito al bot

===== Description

Llama a `getUpdates` de la Bot API de Telegram (timeout 5 s) y resume los chats vistos: `chatId`, `tipo` (private/group/supergroup/channel) y un extracto del último mensaje. Útil para descubrir el `chat_id` de un grupo y configurar `TELEGRAM_CHAT_ID`.
